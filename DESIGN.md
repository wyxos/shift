# Design System: SHIFT

## Overview

**Creative North Star: "The Workbench"**

The Workbench keeps reports, technical context, and follow-up easy to scan. Its character is calm, clear, and practical: compact controls, familiar icons, and restrained emphasis support sustained work.

Cool neutral surfaces carry most of the interface. Signal Blue identifies actions and selection; tonal layers and borders separate working areas. Small shadows support controls and cards, while dialogs and sheets use stronger structural depth. Light and dark themes preserve the same hierarchy.

**Key Characteristics:**

- Compact and restrained controls.
- Semantic blue actions with cool neutral surfaces.
- Responsive lists and task sheets.
- Depth through tonal layers, borders, and modest shadows.

This record describes the incumbent portal, rather than a replacement visual direction.
The source values come from `resources/css/app.css`, the shared UI components, and
Tailwind's installed theme. Browser sampling covered login, dashboard, and a local
fixture task sheet, including its mobile layout. Light-theme values were verified
from source; those browser samples used the dark theme.
The sidecar snippets were checked structurally; their rendering in the live panel
has not been verified.

## Colors

The palette combines Signal Blue with Deep Slate text and Pale Mist supporting
surfaces. Frontmatter preserves the source HSL values. Unprefixed tokens describe
the light theme; `dark-` tokens describe the effective dark theme, including inherited
values. Color names below describe those roles without replacing their CSS names.

### Primary

- **Signal Blue** (`primary`): filled actions, selected options, links, and selected
  content. The dark counterpart is brighter and uses dark text on filled actions.
- **Focus Blue** (`ring`): keyboard focus and active field borders. Its dark value
  is lighter than the dark action blue.
- **Logo Blue** (`brand-symbol`): the approved ribbon symbol in `public/brand/`.
  Its value is separate from the UI action palette.

### Neutral

- **Deep Slate** (`foreground`, `card-foreground`, `popover-foreground`): reading
  text and headings in light mode; the dark counterparts become pale text.
- **Cool White** (`background`, `card`, `popover`): page and contained surfaces
  in light mode; dark mode separates navy page backgrounds from lighter cards.
- **Pale Mist** (`secondary`, `muted`, `accent`): supporting controls, quiet
  surfaces, and hover/selection backgrounds.
- **Muted Slate** (`muted-foreground`): supporting copy and metadata.
- **Cool Dividers** (`border`, `input`): surface separators and field boundaries.
- **Navigation Mist** (`sidebar-*`): navigation surfaces, text, selection, and focus.

### Semantic and Data Colors

Danger text uses `destructive`; filled danger controls use `destructive-surface`
and `destructive-hover` with `destructive-foreground`. In dark mode the text red
lightens while the filled control retains its solid crimson treatment.
The five `chart-*` roles are the dashboard's data palette, with separate dark values.

**The Semantic Color Rule.** Use existing theme roles for controls, surfaces, and text. Keep the logo color tied to the approved assets; it is a distinct value from the action color.

**The Theme Pair Rule.** Apply the matching dark role when the dark theme is active. Danger text and filled danger controls use separate roles in dark mode.

The sidecar's eight-step tonal strips are generated display aids, not additional
application tokens or approved contrast pairs.

## Typography

**Interface font:** Instrument Sans followed by the source system sans and emoji
fallbacks. The document shell's webfont links are commented out and no active
font-face declaration was found. Preserve the fallback stack; computed font-family
does not establish that Instrument Sans itself was loaded.

**Code font:** the system monospace stack used by rich-text code blocks and
technical details. The outlined logo lettering belongs to the brand SVG assets
and does not create a second interface font.

The interface uses medium weight for controls and semibold for working headings,
with regular text for reading and metadata. It has no separate display type system.

| Role | Existing use |
| --- | --- |
| `headline` | Dashboard page heading (24px, semibold, 32px line height, tight tracking). |
| `title` | Task-list heading (18px, semibold, 28px line height). |
| `auth-title` | Login heading (20px, medium, 28px line height). |
| `metric` | Dashboard totals (30px, semibold, 36px line height). |
| `body` | Default text and mobile field text (16px, 24px line height). |
| `body-compact` | Descriptions, list content, and desktop fields (14px, 20px line height). |
| `label` / `button-label` | Medium control labels, with tight field-label or regular button line height. |
| `caption` | Supporting metadata (12px, 16px line height). |
| `code` | Rich-text code blocks (14px, line height 1.5). |

Responsive inputs retain 16px text below the medium breakpoint and use 14px above it.
Task titles truncate in lists; technical text wraps or scrolls in its own container.

## Layout

The portal uses an inset sidebar shell. Desktop navigation is 16rem wide and
collapses to a 3rem icon rail, with extra padding in the inset wrapper; the main
surface gains an 8px outside margin and
rounded corners on desktop. The shell header holds breadcrumbs, appearance,
and notifications. Working pages generally use 16px padding and 16px gaps.

The repeated spacing rhythm uses 4px steps plus a 6px compact gap. Cards use 24px
vertical padding and 24px horizontal padding in header/content children. Authentication
uses a centred column with a 24rem maximum width, 24px outer padding on small screens,
and 40px at the medium breakpoint.

- Small (640px): task-list header/actions can form a horizontal row; dialogs use
  their bounded desktop width.
- Medium (768px): desktop sidebar styling and smaller field text apply. The sidebar
  provider separately tests `max-width: 768px`; preserve this existing boundary
  rather than assuming the CSS and provider switch identically at exactly 768px.
- Large (1024px): task tables replace compact record lists; task details and comments
  can appear side by side. Below it, Details and Comments select one pane.
- Extra large (1280px): task sheets occupy 75vw, capped at 72rem (1152px).
  Smaller widths use the full viewport; wide desktop screens retain the same cap.

The generic sheet preset differs: full viewport below medium, half viewport at
medium, and content-fit with an 800px minimum at extra large. Keep the task preset
for task editing. Inner panes scroll within the fixed-height sheet.

## Elevation & Depth

Depth is structural. Tonal changes and thin borders carry the basic hierarchy;
small shadows support buttons and cards. Dialogs, sheets, and menus receive
stronger shadows and a dimmed backdrop when applicable. In dark mode, the lighter
card surface remains an important depth cue even when a shadow is less visible.

### Shadow Vocabulary

- **Control** (`shadow-xs`): a small edge under filled/outline buttons.
- **Container** (`shadow-sm`): cards and the desktop inset working surface.
- **Overlay** (`shadow-lg`): dialogs and sheets.

Exact source shadow values live in the sidecar's `extensions.shadows`.

**The Structural Depth Rule.** Use tonal separation and borders for grouping; reserve the stronger overlay shadow for dialogs, sheets, and floating menus.

## Shapes

Controls have gently curved corners (6px). Small interactive details use 4px
corners; dialogs and compact-list containers use 8px; cards and the desktop inset
surface use 12px. Full rounding is used by existing circular avatars and similar
round elements, rather than applied to every control.

Borders are generally one pixel. Standard fields and containers use solid borders;
read-only/original-submission areas can use dashed borders. Keep the existing
component-specific geometry rather than applying one radius everywhere.

## Components

### Buttons

Compact and restrained. The default button is 36px high with 6px corners, 14px
medium text, an 8px gap, and 16px horizontal padding (12px when a direct icon is
present). Small buttons are 32px high; large buttons are 40px; icon buttons are
36px square. Common icons are 16px.

- **Primary:** Signal Blue with its paired foreground; hover reduces fill opacity.
- **Secondary:** Pale Mist with supporting foreground; hover reduces fill opacity.
- **Outline:** bordered page surface; dark mode uses a translucent input surface.
- **Ghost:** transparent until hover, then the accent surface.
- **Link:** primary text with an underline on hover.
- **Destructive:** solid danger surface and its dedicated darker hover role.

Keyboard focus uses a ring and border treatment. Disabled controls suppress pointer
actions and use reduced opacity. Invalid states use danger borders and a theme-aware
danger ring. Button-group options reuse small buttons, wrap with an 8px gap, and
preserve radio or toggle semantics and arrow-key navigation.

### Chips and State Badges

Small badges use 6px corners, 12px semibold text, and compact padding. The shared
task-state badge uses a lightly tinted neutral surface, a border, an icon, and a
text label. Status and priority remain distinguishable without depending on color.

### Cards and Containers

Cards use the card surface/text pair, 12px corners, a one-pixel border, a small
shadow, and 24px content spacing. Dense record lists use rows and dividers rather
than turning each desktop row into a card. Empty compact lists retain the same
bounded container and a centred message.

### Inputs and Fields

Fields are 36px high with 6px corners, a one-pixel input border, 12px horizontal
padding, and 4px vertical padding. Light mode is transparent; dark mode adds a
translucent input surface. Focus changes the border to Focus Blue. Placeholder text
uses Muted Slate. Disabled and invalid states remain explicit.

Labels use 14px medium text. Reuse the existing custom pickers and searchable
collaborator/project controls; keep their selected, empty, and keyboard states.

### Navigation

Sidebar items use compact icon/label rows, 6px corners, and pale tonal hover/active
backgrounds. Active labels gain medium weight. The standard row is 32px high;
the logo row uses the larger variant. Icon collapse retains the standalone symbol
and supporting tooltips. Mobile navigation uses a sheet.

### Task Sheets and Threads

Task creation/editing belongs to the canonical task-list sheet flow. A back action
and title lead the sheet; metadata and editable controls precede description,
collaborators, attachments, and discussion. Desktop panes sit side by side where
space permits; mobile uses Details and Comments choices.

On phones, Comments uses the sheet's 16px gutter without an additional card border
or horizontal inset. Discussion history and bounded reply editors use the shared
themed scrollbar. Short viewports allow the discussion pane to scroll so the reply
controls remain reachable.

Error reports add Task / Events tabs, with Events initially selected. Rich-text
content preserves paragraph/list spacing, bordered code blocks, and inset reply
quotes. Reply quotes use a stronger left border and a subtle tonal fill.

### Motion and Focus

Ordinary state transitions use the installed 150ms default. Sidebar width/location
transitions use 200ms linear easing; dialogs use 200ms; sheets specify 500ms opening
and 300ms closing with ease-in-out. These are observed values, not a new timing policy.
Reduced-motion overrides shorten transitions/animations and remove smooth scrolling.

Row actions retain their layout space and tab order while concealed on fine-pointer
devices; hover or focus-within reveals them. Touch users retain visible actions.
Keyboard focus remains visible, including the row-action inset underline.

## Do's and Don'ts

### Do

- Do reuse the existing semantic colors, shared controls, and task presentation helpers.
- Do preserve the light/dark role pairs and readable invalid, disabled, and selected states.
- Do keep compact controls, wrapping action groups, and the existing responsive list/sheet patterns.
- Do preserve visible keyboard focus, labelled icon actions, and reduced-motion overrides.
- Do use the approved logo, theme-appropriate wordmark, and standalone symbol for collapsed navigation.

### Don't

- Don't substitute the logo blue for the UI primary token.
- Don't turn every status or priority badge into a saturated color block; the shared state badge uses an icon and label on a neutral surface.
- Don't assume Instrument Sans is downloaded or present on every device.
- Don't turn illustrative docs screenshots into the authority for portal tokens.
- Don't replace shared task components with independently styled portal copies.
